# Native parallel execution adapter

Orchestration belongs to `$protocol`. Approval of the plan or done block authorizes dispatch of useful independent work without a separate spawn/worktree question. The coordinator owns the result and all convergence; no standalone `/orchestrate` stage is needed.

## Shared authority and fallback

Load the canonical organization procedure once: `cc skill get parallel-execution --scope machine --json`. Apply its returned `content`; do not maintain a copied organization policy here. This file is the native adapter and minimum safe fallback when no organization layer is installed. Missing optional organization policy is reported, not invented. The shared engine is `tc cycle`, not an in-repo scheduler. If it is missing, restore the shared tooling before multi-writer dispatch; never silently replace validation with prose.

## Plan and dispatch

1. Preserve the approved outcome, acceptance, budget, cumulative attempts, design decisions and exclusions in `tc`. Make independent deliverables the scopes: a backend stream may contain several independently ownable outputs. A dependent edge names the actual input or decision, never merely a specialist phase. Interfaces can unlock consumers before provider implementation finishes. Coupled work goes to one agent with the reason recorded. Every role and stage divides (2026-11-05): when a stage's work divides, dispatch several agents of the same role on disjoint partitions in parallel, with one synthesis owner per stage merging partial results with provenance and keeping contradictions visible; a flow arrow is a stage boundary, not a single agent; one agent per stage only when its work is genuinely indivisible, with the reason recorded.
2. Build schema-version 1 cycle data for `tc cycle plan --file PLAN --json`: `id`, `task`, `runtime` (`codex`), absolute existing `root`, positive worker `capacity` within the current native ceiling, `resourceLimits`, and `streams`. Each stream declares `id`, `task`, `role`, `kind` (`code`, `research`, `design`, `qa`, `operations`), `paths`, `readOnly`, `dependsOn` (`stream`, required `event`, concrete `reason`), `resource`, and explicit `worktree` for every writer plus `branch` for code writers (read-only scopes need neither). Validate with `tc cycle validate --file PLAN --json` before persisting or creating resources. Restrict ownership paths to literals/directories or terminal `/**`; ambiguous wildcard claims, traversal and escaping symlinks are refused. Shared files have one owner; builders return separate contributions to that owner.
3. Read `tc cycle ready CYCLE --json`. Claim each ready scope with `tc cycle claim CYCLE STREAM --agent ID --cwd PATH [--branch REF] --json`. Capacity is actual available native worker slots, excluding the coordinator, and resource permits. Native runtime ceilings cannot be raised by this policy. Admit expensive setups/builds/browser suites/database work separately; continue light ready work during contention instead of retry storms.
4. Announce the fan-out in one line: running scopes, queued scopes and their actual wait reason. Use the runtime's real `spawn_agent` mechanism, not a fabricated agent type or a CLI provider loop. Give each worker one specialist skill, task/cycle/stream identity, owned and forbidden outputs, agreed inputs, checks and stop condition. Before native launch, consume the claim-bound permit with `tc cycle verify-dispatch CYCLE STREAM --role ROLE --cwd PATH --json`; reject a wrong role/root or reused permit. Persist the returned native agent identity with its receipt. Confirm `pwd`, repository root, assigned branch/base and canonical task database before writes. A worktree alone or `--add-dir` never proves actual cwd.
5. Each writer uses its own working directory/worktree and index. Read-only research and independent review may share sources; separate output ownership is enough when no mutable checkout is needed. Read `tc cycle adapter PROJECT --json` for the setup/readiness/isolation/focused-check/integration/teardown contract declared in `.copilot/worktree-adapter.json`; discovery executes no setup. Missing stateful isolation is a hold, and a filesystem-only fallback proves no database isolation. Worktrees do not isolate ports, credentials, tenants or databases.
6. Refill native capacity whenever a scope completes or an input becomes ready. Use `tc cycle record CYCLE STREAM --event contract|built|integrated|accepted|rejected|held|released|stopped --file RECEIPT --json` for observed state and evidence. These commands authorize no provider call or deletion; recorded readiness alone is not a native launch receipt. After observing native worker exit, record `stopped` with its claim lease token, `stopped:true` and runtime exit artifact. Preserve failed launches and release abandoned claims before reassignment, never erase attempt history.

## Converge and verify

Builders commit locally, run focused checks and never push. One integration owner merges compatible completed contributions as they become useful while unrelated work continues. Every role converges through one synthesis owner per stage who merges partial results with provenance and keeps contradictions visible: research by evidence synthesis and explicit disagreement, design through comparable alternatives and the real owner decision, and strategy, UX, copy, architecture, development, security, documentation, operations, sales and finance by the same owner-merge with disagreements preserved. Neither is solved by concatenation or majority vote.

Verification is divisible work (2026-11-05): split test, QA and verification by acceptance criterion, user journey, surface, test file or shard, and browser/viewport, with one agent per partition run in parallel within resource permits; when at capacity, queue browser partitions rather than merging them into one run. One QA convergence owner merges per-partition evidence, all recorded against the same integrated source identity, into one verdict and runs the cross-partition seam checks. The integration owner runs only the smoke/integration checks needed to integrate; the full suite goes to the QA partitions. A single agent running a full suite is a coupled exception that requires a recorded reason. Independent QA covers the assembled candidate in these partitions plus cross-scope (cross-partition) seams. A builder never supplies its own independent QA verdict. Register each detached review's actual execution root and preserve the existing task/contract/source/runtime bindings. The coordinator aggregates coverage into one current verdict. Disjoint fixes run in parallel again; rerun changed scopes and affected consumers/integration checks. Reuse evidence only when the declared source identity remains identical. Full integration checks run once per tested candidate where required, not once per worker push and not once forever. T1/T2 keep their proportional attestation; T3 keeps independent evidence-bound QA.

## Finish and retire

Record resource creation receipts when provisioning: cycle, stream, path/branch, immutable identity, owner, consumers, recovery and retirement conditions. `tc cycle cleanup-plan CYCLE --json` prepares the exact packet. Recheck integrated reachability, clean tracked/untracked/ignored state, active workers/consumers, teardown and identity drift. Preserve dirty, unique, unmerged, active or uncertain resources with a named owner and next action. The owner explicitly authorized automatic removal of merged worktrees during cleanup on 4 November 2026. Run `tc cycle cleanup CYCLE --json` for receipt-matched, fully integrated, clean and inactive worktrees only after successful teardown and fresh identity/consumer checks. Never remove the coordinator’s current worktree. Keep branch history by default; branch deletion and other resources remain subject to their exact authority, including the separately approved managed synthetic Docker exception. Hold dirty, unmerged, drifted, active or unknown resources. Verify actual removal; cleanup-plan alone is not retirement. Complete agents with supported native lifecycle controls and verify the scoped agent list. Enumerate every body/PRD/stream task, including parked tasks, through the canonical task-closeout procedure. Complete verified work through its existing QA gates; cancel abandoned or superseded work with the original requirements, failure evidence and resume handoff preserved. Never delete task records or mark unresolved acceptance complete. Verify workers stopped and inactive claims cleared. Close streams and the PRD only after no pending, blocked, in-progress or running work remains; a genuine unresolved obligation keeps the body open with its owner and next action. Re-query persisted task and claim state before reporting the PRD finished.

Report delivery accepted, cleanup pending approval, held work and cleanup complete distinctly. Release, external posting, deployment and shared persistent migrations retain their existing authority and one serial owner.

## Cheap proof

Run `tc cycle smoke --json` to exercise shared engine lifecycle across the active specialist role labels using short deterministic local subprocesses. The installed bundle also includes `scripts/protocol-cycle.py` adjacent to `agent-catalog.json`; invoked by its resolved plugin path it derives roles without depending on the consuming project cwd. From a framework source checkout, `python scripts/protocol-cycle.py smoke --json` is a thin wrapper around that same bundled adapter; its `--include-optional` includes dormant role labels without activating their packs. This spends no model tokens and is not proof of native agent reasoning or runtime dispatch. A separate minimal live native fan-out with tiny scopes checks actual runtime spin-up/completion; record its real identities and overlap, then reuse the deterministic check for routine regressions. Never run a provider benchmark implicitly or imply this smoke proves end-to-end speed improvement.
