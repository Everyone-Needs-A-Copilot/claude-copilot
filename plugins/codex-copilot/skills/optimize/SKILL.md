# Optimize

Read [the shared work lifecycle](references/work-lifecycle.md) once per task.
Use its small checkpoint for ordinary work and full retirement procedure when
asked to optimize a repository or completed body of work.

Start from the actual branch, working tree, task authority and consumers. Maintain
one current narrative in the existing structure, keep execution and QA authority
in `tc`, and use `cc` memory as a scoped pointer instead of another history copy.
Apply a relevant lesson to a decision or check, or record no applicable lesson;
record later measured outcomes separately from recorded or applied learning.

Prepare an exact retirement manifest and verified recovery before requesting
destructive approval. Protect required software, LLM stubs, original evidence,
unique developer work and active dependencies. Report actual removals and net
file/byte change including archives and proof artifacts, alongside explicit holds.
A summary or archive alone is not completed cleanup.

For substantial QA-required work, register an observable `WORK-LIFECYCLE` or
equivalent criterion before freezing the acceptance contract. Use existing tc v2
source-bound QA; these instructions do not install an unbypassable runtime hook.
Do not expand an already frozen task or reset its cumulative execution history.
