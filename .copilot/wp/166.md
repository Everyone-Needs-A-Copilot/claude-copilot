## AXIS B — Is the "CONSOLIDATE is a deliberate One-Direction-Principle choice" defense sound, or circular?

- **Documented** at `knowledge-copilot/00-best-practices/04-knowledge-vs-capability-boundary.md:42-48`, with rationale: *"Knowledge flows out of closed silos into open files. That flow is read-only and one-way... The moment you push data back into a closed silo, you become a sync engine and the vault stops being canonical."* Real, load-bearing best-practice doc.
- **CRITICAL — what it actually forbids:** only **vault → closed-silo** two-way sync. It does **not** forbid promoting running-system content **into** the vault. The same doc explicitly *endorses* inbound flow: *"A source silo is something to drain"* (`:46`) and lists "Notion migration output → Vault" as correct (`:71`).
- **Date:** git shows the doc added **2026-06-28** ("add knowledge-vs-capability best-practice"), one day before the 06-29 research — but it is *"Distilled from the decision instrument of the (now-retired) everyone-needs-knowledge-management product, 2026-06-28"* (`:5`), and the one-direction *concept* appears earlier in archived decisions (conversations-copilot NocoDB: *"one-direction import pipeline... not a bidirectional sync"*). So the **concept predates**; the **formal write-up is ~contemporaneous** with the research. Mild post-hoc-formalization signal, but not the core problem — the core problem is misapplication (below).

### B.2 — Do promotion paths actually exist? (case i / ii / iii)
