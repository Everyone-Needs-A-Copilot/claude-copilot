# Technical Design: Structured Verdict Channel for the Copilot QA Gate

**Task:** TASK-151 | **PRD:** PRD-7 (Framework Hardening: Failable QA Gate)
**Repo:** `/Volumes/Dev/Sites/CSE/claude-copilot` (global framework install behind `~/.claude/copilot`)
**Status:** Proposed
**Author:** @agent-ta

---

## 0. BLUF

Replace prose-parsing with a **tc-database-backed verdict record, queried by session**, written by the agent through a new `tc qa` subcommand and read by `subagent-stop.sh` as a field. The hook stops inferring both the *subject* (which task) and the *decision* (pass/fail) from unbounded natural language. Freshness is enforced by a per-arm-cycle nonce minted by the hook, not by trusting the record's own timestamp. **This closes the parsing-ambiguity class completely and closes nothing else** — the agent still authors its own verdict, so the `ARTIFACT:` evidence requirement must carry over intact and, in a later phase, be verified hook-side against the harness transcript rather than merely asserted.

---

## 1. Problem statement (what actually broke, three times)

`subagent-stop.sh` learns the outcome of a QA round by regex-scanning `last_assistant_message`:

- `extract_task_id()` — finds header-shaped `Task: TASK-N` lines to decide *which* task.
- `parse_qa_verdict()` — finds `VERDICT: APPROVED|APPROVED-WITH-MINOR-FIXES|REJECTED` to decide *what happened*.
- `has_artifact_marker()` — finds `ARTIFACT: <type>|<detail>` as the anti-rubber-stamp evidence requirement.

Three review rounds each found a **new instance of one class**: *content the agent QUOTED or EMBEDDED being read as content the agent AUTHORED.*

| Round | Vector | Effect |
|-------|--------|--------|
| 1 | Markdown decoration (`**Task:**`, `- Task:`) not tolerated | Gate could never self-heal; wedged permanently (TASK-129 accumulated 7 identical WARNs while `retries` stayed `{}`) |
| 2 | Loosening admitted blockquoted (`> Task: TASK-999`), fenced, and indented content | Wrong-task attribution; live-reproduced |
| 3 | Fence tracker conflated ``` and `~~~`; a stray tilde run closed a backtick fence | `Task:` line smuggled out of a fence; live-reproduced |

Each individual fix was correct. The *class* is not closeable by better parsing: the message is unbounded, adversarially-shaped, model-authored Markdown, and the hook is making a security-adjacent decision from it. The current `extract_task_id()` is now a hand-rolled partial CommonMark implementation (fence-char tracking, fence-length matching, indented-code detection, blockquote detection, emphasis stripping) — approximately 100 lines of parser whose *correctness* is the gate's correctness. That is the wrong dependency.

**The design goal is not "a stricter parser." It is: the hook must never pattern-match prose to reach a decision.**

## 2. Constraints discovered by inspection (these shape the answer)

These were verified empirically in this repo and the research-copilot consumer, not assumed:

1. **`CLAUDE_CODE_SESSION_ID` inside a subagent's Bash tool equals the `session_id` the SubagentStop hook receives.** Verified: a subagent Bash probe returned `8b041ff4-b0ee-436b-8105-042ebacea324`, which is exactly a top-level key in `/Volumes/Dev/Sites/COPILOT/research-copilot/.claude/hooks/state/qa-gate.json` (a file only `subagent-stop.sh` writes, keyed off the payload's `session_id`). **This is the load-bearing enabler**: the agent can address the same session the gate is keyed on, so a record can be bound to the session without the hook ever parsing prose to find it.
2. **Agents do NOT get `COPILOT_HOOK_STATE_DIR` or `CLAUDE_PROJECT_DIR`.** The shim exports `COPILOT_HOOK_STATE_DIR` only into the hook process (`copilot-hook.sh`: `export COPILOT_HOOK_STATE_DIR="${PROJECT_DIR}/.claude/hooks/state"`). A subagent env probe shows neither variable. **Consequence: an agent cannot reliably construct the state-dir path itself.** Any file-drop mechanism therefore requires a helper that resolves the path — which means the helper, not the path, is the real interface.
3. **`.claude/hooks/bin/` is NOT vendored into consuming projects.** Projects carry only `copilot-hook.sh` (plus project-owned `post-edit-verify.sh`, `user-prompt-protocol.sh`). Confirmed by listing research-copilot's `.claude/hooks/`. **This is a live latent defect, surfaced by this analysis:** `qa.md` instructs `adversarial_artifact="$(.claude/hooks/bin/adversarial-pass.sh)"` as a project-relative path, so the adversarial pass is silently a no-op in every consuming project. It degrades safely (empty output, gate still passes on `test-run`), but it means **"tell the agent to run a script under `.claude/hooks/bin/`" is not an available mechanism.** Fix separately; noted here because it eliminates an otherwise-obvious option.
4. **`tc` is a single global install on `PATH`** (source at `tools/tc/src/tc`, one install serving every project). It resolves the project from cwd. This gives it the same "fix it once, every project gets it" property as the global hook rules — the property the whole shim architecture exists to preserve.
5. **The hook already shells out to `tc`** — `task_id_valid_in_project()` runs `( cd "$project_dir" && tc task get "$num" --json )`, guarded by `command -v tc &>/dev/null || return 1`. The dependency direction **hook → tc** is established, tested, and already fails safe when `tc` is absent.
6. **`tc`'s schema uses `CREATE TABLE IF NOT EXISTS` with a `schema_version` table**, so an additive table is a low-risk migration.
7. **Subagents are already exempt from the gate's own deny logic** (`rule_qa_gate()`: `if [[ -n "$AGENT_TYPE" && "$TOOL_NAME" != "Agent" ]]` → allow for a recognized agent type). So @agent-qa and @agent-me can run a new `tc` subcommand while the gate is armed without any `QA_GATE_SAFE_PREFIXES` change. A prefix entry is still wanted for the main session's diagnostic use.

## 3. Mechanism options

### Option A — Agent writes a verdict file to a known path under `COPILOT_HOOK_STATE_DIR`

The agent writes e.g. `${COPILOT_HOOK_STATE_DIR}/verdicts/<session>-<task>.json`; the hook globs the directory.

- **Binding to task+session:** filename and/or file body carries `session_id` + `task_id`. Hook matches on `session_id == payload.session_id` and `task_id ∈ pending_tasks`.
- **Anti-replay:** requires an explicit nonce + a consume/delete step, plus a `created_at > armed_at[tid]` check. Deleting a consumed file is easy but must be crash-safe under the existing lock.
- **Agent forgets:** no file → hook falls through to the same no-verdict handling as today.
- **Fatal problem (Constraint 2):** the agent cannot resolve the path. It has neither `COPILOT_HOOK_STATE_DIR` nor `CLAUDE_PROJECT_DIR`. Telling agents to guess `./.claude/hooks/state/` couples every agent definition to hook-internal layout and breaks whenever cwd isn't the project root — precisely the fragility the shim architecture exists to prevent.
- **Secondary problems:** raw agent-authored JSON can be malformed and wedge the reader (a new failure mode replacing the old one); no schema validation; a second file-format contract to version; and it re-vendors knowledge of hook layout into agent prompts.
- **One real advantage:** works with zero dependency on the `tc` database being present or healthy.

**Rejected as the primary mechanism.** Retained as the emergency-path reasoning in §5 (what happens if `tc` is unavailable).

### Option B — Agent calls a `tc` subcommand that records the verdict (RECOMMENDED)

New verb group `tc qa`, backed by an additive `qa_verdicts` table in the project's `.copilot/tasks.db`. The hook queries it **by session** — never by a task id it had to parse.

- **Binding to task+session:** the agent passes `--task N` explicitly and `tc` stamps `session_id` from `$CLAUDE_CODE_SESSION_ID` (Constraint 1). The hook then queries `tc qa verdict list --session "$SESSION_ID" --unconsumed --json` and independently cross-checks each returned `task_id` against `pending_tasks` for that session. **The hook never needs the agent to tell it which task in prose, and never trusts the agent's session claim without matching it to its own payload value.**
- **Anti-replay / staleness (the important part):** a nonce minted **by the hook at arm time**, not by the agent.
  - When `handle_me_completion()` arms a task, it writes `arm_nonce[tid] = <random-128-bit-hex>` into `qa-gate.json` alongside the existing `armed_at[tid]`. Same additive-field pattern already used for `armed_at`/`last_parse`.
  - The QA agent obtains the nonce from `tc qa gate status --json` (a read-only helper that reads `qa-gate.json`… see the layering note below) or, preferably, from the arm-time `systemMessage` and the deny-message diagnostic, so it never has to read hook state directly.
  - The hook accepts a verdict record only if `record.nonce == arm_nonce[tid]`. On accept it deletes `arm_nonce[tid]` (arm cycle over) and marks the record consumed.
  - **Replay of an old record fails** because the next arm cycle mints a fresh nonce. **A record written for a different session fails** the session match. **A record written before the current arm** fails both the nonce check and the `created_at > armed_at[tid]` check.
  - The nonce is **not a secret** — the agent can read it. Its job is *freshness*, not authentication. See §4; this distinction is the honest core of the design.
- **Agent forgets to write one:**
  - *Verdict path:* the hook finds no unconsumed record for any pending task → treated exactly like today's unparseable-verdict case, i.e. **fail closed** (gate stays armed) with the existing self-heal ladder underneath it: single-pending attribution charges it as a failed round → `retries[tid]++` → 3-strikes auto-unblock; and the read-side 24h staleness release is the outer backstop. So "agent forgot" is bounded at 3 QA rounds, not indefinite.
  - *Arm path (@agent-me forgets):* the gate never arms → **fails open**, identical to today's behavior on an unparseable `Task:` header. This is a pre-existing property, not a regression introduced here, and it is the correct direction: an un-armed gate is a missed block, an incorrectly-armed gate is a wedge.
- **Layering note (matters):** `tc` must NOT learn the hook's state-dir layout. `tc qa verdict record` writes only to `tasks.db`. The nonce travels *to* the agent through hook-authored channels (systemMessage / deny diagnostic), and is *validated* only by the hook. `tc qa gate status` — if built at all — is a thin convenience that shells nothing and is explicitly optional; the hook remains the only writer and validator of `qa-gate.json`. Dependency direction stays one-way: **hook → tc**, matching the existing `task_id_valid_in_project()` precedent, and keeping `tc` agent-agnostic (it is also consumed by codex-copilot).
- **Costs:** one `tc` invocation added per QA SubagentStop (the arm path already pays one). A `tc` schema migration. A capability probe for tc-version skew (§6).

### Option C — Hybrid: prose marker POINTS at a structured record

Agent emits `VERDICT-REF: <uuid>`; hook greps that one token and dereferences it.

- **Binding/replay:** identical to B once dereferenced (the nonce still does the real work).
- **Why rejected:** it *keeps a prose parser in the decision path*. A quoted or fenced `VERDICT-REF:` is exactly the Round-2/Round-3 shape again, just with a narrower payload. The nonce would catch a *stale* quoted ref, but a quoted ref to a *currently valid* record (e.g. QA quoting the record it is about to reference, or quoting a sibling agent's output in a review) is still a live wrong-attribution vector. More importantly it buys nothing: the hook already knows `session_id`, so **querying by session is strictly more reliable than being told a reference**. Adding a parser to avoid a query is a pure downgrade.
- Retained only as a **transitional read** during Phase 2 dual-read if a lookup-by-session proves insufficient in some harness edge case — not planned.

### Recommendation

**Option B.** It is the only option where the hook's decision inputs are all fields, all cross-checked against state the hook itself wrote, and where the agent needs no knowledge of hook-internal paths. It reuses the established hook→tc dependency and the global-single-install property, so a fix reaches every project without touching any project's vendored shim.

## 4. Trust boundary — stated plainly, without overselling

**The agent authoring the verdict is the same party the gate constrains. This design does not change that.**

### What this design DOES defend against

1. **The entire quoted-vs-authored ambiguity class.** Blockquotes, fenced blocks, tilde/backtick fence confusion, indented code, markdown emphasis, table cells, nested-agent output pasted into a summary — none of it can any longer be mistaken for an authored decision, because **no prose is read at all** on the decision path. This is the class that produced three consecutive live-reproduced bypasses; it is closed, not narrowed.
2. **Wrong-task attribution.** The subject of the verdict is an explicit `--task` field, cross-checked against `pending_tasks` for the hook's own `session_id`. A copy-pasted, stale, or cross-project task id cannot silently retarget a clear or a penalty.
3. **Stale and replayed records.** The hook-minted per-arm-cycle nonce plus `created_at > armed_at[tid]` plus consume-on-accept means a verdict is valid for exactly one arm cycle of one task in one session.
4. **Gate wedging on formatting.** The Round-1 failure — a gate that could never self-heal because QA's ordinary markdown habits defeated the parser — becomes structurally impossible: there is no formatting to get wrong.
5. **Cross-session bleed.** `tc` stamps `session_id` from the environment; the hook accepts only records matching its own payload `session_id`.

### What this design does NOT defend against — be clear about this

1. **An agent asserting a pass it did not earn.** `tc qa verdict record --task 5 --verdict APPROVED --artifact 'test-run|pytest ... exit=0 "5 passed"'` is a single Bash call. Nothing stops an agent from making it with fabricated artifact text. **A structured channel removes parsing ambiguity; it does not create authority.**
2. **Anything an unconstrained Bash tool can do.** Any agent, or the main session, can write any verdict record, and can also `COPILOT_QA_GATE=off`. There is no key, capability, or signature the agent does not have. **This is not an authentication boundary and must not be described as one in docs or release notes.**
3. **Fabricated evidence.** Until Phase 4 (below), `ARTIFACT:` content is still a claim about a command, not proof that the command ran.

### Therefore: what carries over, unchanged and non-negotiable

- **The `ARTIFACT:` evidence requirement carries over in full.** It is the *only* anti-rubber-stamp control in the system, and it becomes *stronger* in structured form: today it is `grep -qiE '^[[:space:]]*ARTIFACT:...'` over prose (and is subject to the exact same quoting class as the verdict); in the new channel it is a **required, typed, validated field**. `tc qa verdict record` **must reject** an `APPROVED` / `APPROVED-WITH-MINOR-FIXES` verdict submitted without at least one well-formed artifact of type `test-run | file-check | diff-check | adversarial-run`. Validation moves from the hook (post-hoc, greppy) to the CLI (at write time, schema-enforced), which also gives the agent an immediate, actionable error instead of a silent non-unblock.
- **Hook-side verification of the cited artifact is the real next increment, and it is where the trust boundary actually moves.** Two rungs, in increasing strength:
  - *Cheap, available now (Phase 3):* for `file-check`, the hook can `test -e` the cited path; for `diff-check`, it can confirm the working tree has changes for the task's touched files. Mismatch → reject the pass. This is weak but non-zero, and it costs nothing.
  - *Real (Phase 4, contingent):* Claude Code's SubagentStop payload is documented to carry `transcript_path`. `subagent-stop.sh` currently ignores it (its header says "other fields ignored"). **If present in practice — this must be verified empirically before committing to it** — the hook can confirm that a Bash tool call matching the cited command, with the cited exit status, actually appears in the harness's own record of the session. That moves the claim from *"the agent says it ran tests"* to *"the harness recorded that it ran tests."* That is the first genuine strengthening of the trust boundary available here, and it is **only reachable because the artifact is now a structured field with a parseable command and exit code** rather than free text. It is the strategic reason to prefer Option B beyond ambiguity-removal — but it is Phase 4, contingent, and must not be claimed until proven.
- **Honest one-line summary for release notes:** *"The QA gate now reads verdicts as data instead of parsing prose. This eliminates a class of misattribution and formatting-induced bypasses. It does not, and is not intended to, prevent an agent from reporting a pass it did not earn — the artifact evidence requirement remains the control for that."*

## 5. What must NOT regress

Every guardrail recently added and verified, and its fate:

| # | Guardrail | Fate | Detail |
|---|-----------|------|--------|
| A | Anchored extraction (`extract_task_id`, fence/blockquote/indent aware) | **Superseded** on the primary path; **retained** as Phase-2 fallback | The task id becomes an explicit `--task` field. `extract_task_id()` stays in-tree, unmodified, and is called only when no structured record is found (Phase 2) — it must not be deleted before Phase 5, and must not be "simplified" while it is still a fallback. |
| B | Cross-check extracted id against session `pending_tasks` | **Preserved and strengthened — do not drop it** | This is the highest-value guardrail. It applies **verbatim** to the structured path: a record naming a task not in `pending_tasks[session]` is refused, exactly as a parsed id is today. Structured input makes the id *unambiguous*, not *authorized* — B is what makes it authorized. Deleting B on the grounds that "the field is now explicit" would be the single most likely regression in this work; call it out in review. |
| C | Ambiguity (2+ distinct ids) fails closed | **Preserved, reshaped** | The prose shape (two header lines) disappears. The equivalent structured shape is **two or more unconsumed verdict records for the same session naming different pending tasks in one QA round**. Same rule: refuse to act, log, exit 0 before taking the lock. Additionally: two records for the *same* task in one round → take neither, log (an agent that wrote twice is confused; guessing is the failure mode C exists to prevent). |
| D | Per-task `armed_at` + read-side staleness release in `rule_qa_gate()` | **Preserved, unchanged, and extended** | `armed_at[tid]` keeps its exact current write/delete lifecycle (set only on first entry into `pending_tasks`; deleted on every exit — pass, full clear, 3-strike). `arm_nonce[tid]` is written and deleted **in lockstep with `armed_at[tid]`, at every one of those same sites** — a nonce that outlives its arm cycle is precisely the stale-timestamp bug D was written to fix, re-created in a new field. The read-side 24h release in `pretool-check.sh` is untouched and remains the outer backstop for "no verdict ever arrives." |
| E | `last_parse[tid]` diagnostic in the deny message | **Preserved, better content** | Still written at mutation time (the read side in `pretool-check.sh` has no access to `$LAST_MSG`). Content improves from "how the regex read your prose" to a precise structured reason: `"no verdict record found for TASK-N (nonce <prefix>… still outstanding)"`, `"record rejected: nonce mismatch — task was re-armed after the record was written"`, `"record rejected: missing artifact"`. **The deny message is now also the nonce delivery channel** (see §6 Phase 1), which is what lets a confused QA agent self-correct instead of looping. |
| F | 3-strikes auto-unblock (`MAX_RETRIES=3`) | **Preserved exactly** | Retry counting is unchanged. A QA round producing **no valid record** counts as a failed round under the existing single-pending attribution rule — this is what preserves the anti-wedge property from Round 1. Do not let "no record" become a silent no-op; that recreates the TASK-129 wedge in new clothing. |
| G | `ARTIFACT:` evidence requirement | **Preserved and strengthened** | Now a required typed field validated at write time by `tc`. `APPROVED` without an artifact is rejected by the CLI with an actionable error, and additionally re-checked hook-side (defence in depth: never trust that the writer validated). |
| H | RC-2: validate task id against *this project's* tc DB | **Preserved, and now structural** | The record lives in *this project's* `tasks.db` and carries an FK to `tasks.id`, so a task id from another project's graph cannot exist in the queried result set at all. Keep the explicit `task_id_valid_in_project()` check anyway on the prose fallback path. |
| I | Single-pending attribution (unparseable fail → charge the sole pending task) | **Preserved** | Applies unchanged when no record is found. It is the anti-wedge mechanism; it must keep working for exactly the reason it was added. |
| J | Subagent exemption from `rule_qa_gate` for non-`Agent` tools | **Preserved** | Required so @agent-qa can run `tc qa verdict record` while the gate is armed. `TOOL_NAME == "Agent"` stays fully gated. |
| K | Lock discipline (`acquire_lock` / `release_lock` / trap) | **Preserved** | Nonce mint and nonce consume both happen inside the existing lock. The `tc` query happens *outside* it (network-free but not instant) — read first, then lock, then re-validate against state read under the lock. |

**Fitness functions to add alongside the change** (per this project's ADR + fitness-function practice — these are automated tests, not review checklist items):

1. **No-prose-in-decision-path:** a test asserting `handle_qa_completion()`'s primary path makes no call to `parse_qa_verdict`/`extract_task_id` when a valid record exists. Enforced by grep on the call graph plus a behavioral test with an adversarial message.
2. **Adversarial-message corpus regression:** feed the Round-1/2/3 reproducers (markdown-decorated, blockquoted, fenced, tilde-smuggled, wrong-task) with a valid structured record present → the record wins, every time, and the message content is provably irrelevant (swap the message body for lorem ipsum; assert identical state transition).
3. **Nonce lifecycle invariant:** `arm_nonce` keys ⊆ `pending_tasks` after every state transition. Asserted after arm, pass, fail, full-clear, and 3-strike unblock.
4. **Artifact-required invariant:** `tc qa verdict record --verdict APPROVED` with no artifact exits non-zero and writes nothing.
5. **Old-shim / old-tc compatibility:** the existing hook test suite runs green with `tc qa` stubbed absent (simulating tc-version skew) — proving the fallback path is live, not vestigial.

## 6. Migration path

### 6.1 Does this need a `PROTOCOL_VERSION` bump or a `PROTOCOL_HARD_MIN` floor?

**No to both. This is a deliberate call and should be recorded as such.**

The vendored shim's declared contract (`copilot-hook.sh` header, `SHIM_PROTOCOL_MIN=1`/`SHIM_PROTOCOL_MAX=1`) is exactly two things: `"<event>.sh <event-name>"` dispatch, and one env var (`COPILOT_HOOK_STATE_DIR`). **This change touches neither.** Every project's existing shim continues to delegate correctly with no edit.

- **Do not bump `PROTOCOL_VERSION` (stays `1`).** Bumping to `2` would make every already-deployed shim (`MAX=1`) trip the skew branch and emit `[copilot-hook] version skew: ...` on **every hook invocation in every project** — a permanent stderr warning about a contract that did not actually change. That is noise that trains people to ignore real skew warnings. Bump `PROTOCOL_VERSION` only when the dispatch convention or the env-var contract genuinely changes.
- **Do not set `PROTOCOL_HARD_MIN`.** That lever exists for genuinely breaking changes and would stop old shims delegating — a direct violation of the framework's stated rule that *a project pinned to an old shim must keep running*. Nothing here justifies it.

**The real skew axis is `tc`, not the shim.** The hook depends on the globally-installed `tc` having the `qa` verb group. Handle it exactly like the existing `command -v tc` guard:

```
qa_verdict_channel_available() {
  command -v tc &>/dev/null || return 1
  ( cd "${CLAUDE_PROJECT_DIR:-$PWD}" && tc qa verdict --help ) >/dev/null 2>&1
}
```

Probe once per hook invocation, cache in a variable. Unavailable → prose fallback, log once at INFO. `tc` is a single global install, so this window closes for every project simultaneously the moment `tc` is upgraded — no per-project migration.

### 6.2 Live `qa-gate.json` state files

Additive fields only, following the exact precedent set by `armed_at` and `last_parse`:

```jsonc
"<session_id>": {
  "pending_tasks": ["TASK-5"],
  "retries": { "TASK-5": 1 },
  "armed_at":  { "TASK-5": "<ISO>" },
  "arm_nonce": { "TASK-5": "9f2c…" },          // NEW — hook-minted, per arm cycle
  "last_parse":{ "TASK-5": "…" },
  "verdict_source": { "TASK-5": "structured" }, // NEW — "structured" | "prose" | "none", diagnostics only
  "history": [ … ],
  "lastSeen": "<ISO>"
}
```

Every reader must fall back tolerantly, per the existing documented rule ("old-shape state files simply lack these keys — every reader falls back tolerantly, never crashes"):

- `arm_nonce[tid]` missing (task armed before this feature shipped) → **accept a structured record on session + pending + `created_at > armed_at[tid]` alone**, log `verdict_source: "structured-legacy-no-nonce"`. Do *not* fail closed on a missing nonce for an in-flight task; that would wedge every gate armed at upgrade time — the exact Round-1 failure mode, self-inflicted at deploy.
- Gates armed pre-upgrade drain naturally within one QA round or, at worst, the existing 24h staleness release.

### 6.3 Does prose parsing stay as a fallback, and for how long?

**Yes, and it is removed on evidence, not on a schedule.** (No time estimates — the exit criterion is a measurement.)

Order of precedence in `handle_qa_completion()` during the dual-read window:

1. Valid structured record for a pending task → **decide from it; ignore the message entirely.**
2. No structured record **and** the tc channel is unavailable (§6.1 probe fails) → prose path, exactly as today, unchanged code.
3. No structured record **and** the tc channel *is* available → **treat as "QA produced no verdict."** Do **not** silently fall back to prose here: a QA agent that could have written a record and didn't is the case we want telemetry on, and silently accepting its prose is how the old path stays load-bearing forever. Charge it as a failed round under single-pending attribution (guardrail I), and make the deny message say precisely that, with the nonce, so the next round self-corrects.

Rule 3 is what actually forces migration. It is also the one behavior change a consumer could notice, so it ships **behind `COPILOT_QA_VERDICT_STRICT=1`** in Phase 2 (opt-in, dogfooded in this repo and research-copilot first) and becomes the default in Phase 3.

**Removal criterion for the prose path (Phase 5):** `verdict_source` telemetry shows zero `"prose"` decisions across dogfood projects for a full release cycle, *and* the shipped `tc` in every reachable install has the `qa` verb group. Until then `extract_task_id()` / `parse_qa_verdict()` / `has_artifact_marker()` stay in-tree with their full test coverage. **Do not refactor or "clean up" the parser while it is still a fallback** — a half-migrated parser is worse than either endpoint.

### 6.4 How projects on old shims behave during the transition

| Project state | Behavior |
|---|---|
| Old shim (`MAX=1`), new global framework, new `tc` | **Full new behavior.** The shim delegates as always; all logic is global. No project-side action required. This is the shim architecture working as designed. |
| Old shim, new framework, **old `tc`** | Capability probe fails → prose path, byte-identical to today. No warning spam, one INFO log. |
| Old shim, **old** framework (project pinned to an older global install via `COPILOT_HOOKS_ROOT`) | Unaffected — it never sees this code. |
| Project with `.claude/copilot-required` | Unaffected. This change adds no new fail-open/fail-closed branch to the shim. |
| `COPILOT_QA_GATE=off` | Unaffected. Escape hatch honored first, as today. |

**No consumer is required to re-vendor its shim for this change.** That is the single most important migration property and it should be stated explicitly in the release notes.

## 7. Agent-side contract

### 7.1 What @agent-qa must emit

Two things, both required, serving two different readers:

**(1) The machine channel — a `tc` call, before the final message:**

```bash
tc qa verdict record \
  --task 5 \
  --verdict APPROVED \                 # APPROVED | APPROVED-WITH-MINOR-FIXES | REJECTED
  --nonce "$QA_NONCE" \
  --artifact 'test-run|pytest tests/test_auth.py::test_login exit=0 "3 passed"' \
  --artifact 'adversarial-run|llm FINDINGS: none found exit=0' \
  --note "…one line, surfaced in the deny diagnostic…" \
  --json
```

- `--artifact` is repeatable and **mandatory for any non-`REJECTED` verdict**; the CLI rejects an approval without one (guardrail G).
- `--nonce` comes from the arm-time `systemMessage` or the gate's deny diagnostic. **If the agent doesn't have it, it omits the flag** — the hook then applies the legacy no-nonce acceptance rule (§6.2) and logs it, rather than the agent inventing a value. Fabricating a nonce must fail; omitting it must degrade.
- `session_id` is **not** an agent-supplied argument. `tc` stamps it from `$CLAUDE_CODE_SESSION_ID` (Constraint 1) and the hook re-checks it against its own payload. **An agent must never be able to assert which session it is in** — that would reintroduce cross-session bleed through a structured field instead of prose.

**(2) The human channel — the prose summary stays, unchanged.** Agent summaries are shown to the user, so the human-readable verdict must not disappear. The closing block in `qa.md` keeps its current shape:

```
Task: TASK-5 | WP: WP-22
ARTIFACT: test-run|pytest tests/test_auth.py::test_login exit=0 "3 passed"
VERDICT: APPROVED
```

**Its status changes, and this must be spelled out in the agent file so the model understands the asymmetry:** once the structured channel is live, these lines are **for the human reader and for the Phase-2 fallback only**. They are no longer what unblocks the gate. Framing this explicitly matters — an agent told "this line no longer matters" will stop emitting it, and it still matters to the person reading the transcript.

### 7.2 What @agent-me must emit (the arm path)

Symmetric, and it must be fixed in the same work — the arm path parses the identical `Task: TASK-N` header and carries the identical defect class:

```bash
tc qa claim --task 5 --json     # "me completed work on TASK-5 in this session"
```

The hook's `handle_me_completion()` reads unconsumed claims for `$SESSION_ID`, still validates each task id against the project DB (guardrail H), and arms — minting `armed_at[tid]` and `arm_nonce[tid]` together. **Fixing only the verdict path leaves half the class open**; arming against a quoted `Task: TASK-999` is the same Round-2 bug on the other side of the round trip.

### 7.3 Where the instruction lives

**In `.claude/agents/_shared/` — one file, included by every agent that participates in the gate.** Today the `ARTIFACT:`/`VERDICT:` contract lives in the body of `qa.md`, with the marker-exemption rule duplicated into every agent's Runtime Precedence section ("a QA `ARTIFACT:` line … always emitted in full regardless of budget"). Duplication across ~16 agent files is exactly why the contract drifted from what the hook actually accepts.

- **New:** `.claude/agents/_shared/qa-gate-contract.md` — the single normative source for: the `tc qa verdict record` / `tc qa claim` invocations, artifact types and format, nonce handling, and the requirement that the human-readable block remain.
- `qa.md` and `me.md` `@include` it. `_shared/output-contract.md`'s existing marker-exemption clause points at it instead of restating the format.
- **Fitness function:** a conformance test asserting the artifact type list in `qa-gate-contract.md`, the allowlist in `tc`'s validator, and the hook's own re-check are the same set. Three copies of one list is how G rots.
- Also fix, in the same pass, `qa.md`'s dead `.claude/hooks/bin/adversarial-pass.sh` relative path (Constraint 3) — either vendor the script or invoke it through a `tc`/`cc` entry point. It is a separate defect but it lives in the same paragraph and would otherwise be re-copied into the new shared file.

## 8. Scope and sequencing

No time estimates. Phases are dependency-ordered and each is independently shippable.

### Phase 1 — Foundation: record the channel, change no decision *(Priority P0, Complexity: Medium)*
**Depends on:** nothing.
- `tc`: additive `qa_verdicts` table (`id, task_id FK, session_id, nonce, verdict, artifacts JSON, note, created_at, consumed_at`) + `schema_version` bump; `tc qa verdict record`, `tc qa verdict list --session --unconsumed --json`, `tc qa claim`. Artifact validation enforced at write time.
- Hook: mint `arm_nonce[tid]` in `handle_me_completion()` alongside `armed_at[tid]`, with delete-in-lockstep at **all four** existing removal sites. Surface the nonce in the arm `systemMessage` and in `rule_qa_gate()`'s deny diagnostic (guardrail E's existing channel).
- Hook: capability probe; write `verdict_source` for telemetry.
- **Decision logic unchanged — prose still decides.** Shipping the channel and the decision separately is what makes Phase 2 a one-line switch with real data behind it.
- *Tests: unit + integration required.* Nonce lifecycle invariant (fitness #3); artifact-required invariant (#4); full existing hook suite green.
- **Breaking-change flag: none.** Purely additive to state file and DB.

### Phase 2 — Dual-read, structured wins *(Priority P0, Complexity: Medium)*
**Depends on:** Phase 1.
- `handle_qa_completion()` and `handle_me_completion()` read structured first; prose becomes fallback per §6.3 precedence.
- Guardrails B, C, F, H, I re-implemented against the structured path (**B especially — see §5**).
- `COPILOT_QA_VERDICT_STRICT=1` gates rule-3 behavior (no-record ≠ silent prose fallback). Dogfood in claude-copilot + research-copilot.
- Agent-side contract shipped: `_shared/qa-gate-contract.md`, `qa.md` + `me.md` includes, dead `adversarial-pass.sh` path fixed.
- *Tests: unit + integration required.* Adversarial-corpus regression (fitness #2) — the Round-1/2/3 reproducers must be provably inert when a record exists; no-prose-in-decision-path (#1); old-tc-absent fallback (#5).
- **Breaking-change flag: behavioral, opt-in only.** An agent that writes no record while `tc qa` is available gets its round charged as a failure *only under the STRICT flag*. Default behavior unchanged.

### Phase 3 — Strict by default + cheap artifact verification *(Priority P1, Complexity: Low)*
**Depends on:** Phase 2 dogfood telemetry showing structured records on essentially every round.
- `COPILOT_QA_VERDICT_STRICT` defaults on; `=0` becomes the escape hatch.
- Hook-side cheap artifact checks: `file-check` path existence; `diff-check` working-tree sanity. Reject a pass on mismatch.
- **Breaking-change flag: yes, for consumers.** Behavior change on the default path. Ships in a minor release with explicit release-note text (§4's honest one-liner) and the `=0` hatch. No shim re-vendor required. **Still no `PROTOCOL_VERSION` bump** (§6.1).

### Phase 4 — Transcript-backed artifact verification *(Priority P2, Complexity: High, CONTINGENT)*
**Depends on:** Phase 3, **and** empirical confirmation that SubagentStop's payload carries a usable `transcript_path`.
- Verify the cited `test-run` command + exit code against the harness's own tool-call record.
- **This is the only phase that genuinely moves the trust boundary** (§4). Everything before it removes ambiguity; this one removes an unverified assertion.
- If `transcript_path` proves unavailable or unstable, **drop this phase rather than substitute a weaker proxy** — a proxy that looks like verification but isn't is worse than an honest gap, given §4's framing.
- *Tests: unit + integration required.* Must include a negative case: a fabricated artifact citing a command never run → pass rejected.

### Phase 5 — Retire the prose path *(Priority P2, Complexity: Low)*
**Depends on:** Phase 3 (Phase 4 not required), plus the §6.3 removal criterion (zero `verdict_source: "prose"` decisions across a full release cycle).
- Delete `extract_task_id()`, `parse_qa_verdict()`, `has_artifact_marker()` and their fallback call sites. Keep the adversarial-corpus tests, repointed at the structured path.
- **Breaking-change flag: yes.** This is the one change that could justify `PROTOCOL_HARD_MIN` — and it still does not, because the shim contract is *still* untouched; the skew axis remains `tc`, and an old `tc` after Phase 5 means the gate simply never arms (fails open, logged) rather than misbehaving. Decide at Phase 5, not now.

### Dependency graph

```
Phase 1 (foundation) ──▶ Phase 2 (dual-read) ──▶ Phase 3 (strict default) ──┬─▶ Phase 4 (transcript, contingent)
                                                                             └─▶ Phase 5 (retire prose)
```

## ADR-014: Structured QA verdict channel replaces prose parsing

**Status:** Proposed

**Context.** The QA gate makes a blocking decision by regex-parsing an agent's unbounded Markdown summary for `Task:`, `VERDICT:`, and `ARTIFACT:` lines. Three consecutive review rounds each found a new bypass of a single class — quoted or embedded content read as authored content — and two were live-reproduced. The parser has grown into a partial CommonMark implementation whose correctness *is* the gate's correctness. Separately, `extract_task_id()` failures caused a permanent gate wedge (TASK-129: seven identical WARNs, `retries` never advancing), because a formatting quirk could defeat the self-heal ladder.

**Decision.** Move the verdict to a structured channel: the agent records it via a new `tc qa` verb group into the project's `tasks.db`; `subagent-stop.sh` queries **by session id** — which the subagent's environment provably shares with the hook's payload — and cross-checks the task against `pending_tasks`. Freshness is enforced by a hook-minted, per-arm-cycle `arm_nonce`, consumed on accept. Prose parsing remains a fallback behind a `tc`-capability probe, and is retired on telemetry evidence rather than on a schedule. No `PROTOCOL_VERSION` bump and no `PROTOCOL_HARD_MIN`: the vendored shim's contract (dispatch + `COPILOT_HOOK_STATE_DIR`) is untouched, so no project must re-vendor.

**Consequences.**
*Easier:* the quoted-vs-authored class is closed rather than narrowed; wrong-task attribution becomes structurally impossible; the gate can no longer wedge on formatting; artifact validation moves to write time with actionable errors; the artifact becomes a parseable field, which is the precondition for real transcript-backed verification (Phase 4).
*Harder:* the hook gains a runtime dependency on `tc` having the `qa` verbs (mitigated by a probe + fallback, and by `tc` being a single global install); one extra `tc` invocation per QA round; a dual-read window during which two decision paths must both be kept correct and tested; nonce lifecycle becomes a new invariant that can rot exactly the way `armed_at` nearly did.
*Sacrificed:* nothing in the trust model — **and that is the point to state plainly.** This buys unambiguity, not authority. The agent can still assert an unearned pass; `ARTIFACT:` remains the only control against that, and only Phase 4 improves it.
*Reversible?* Yes through Phase 3 — the prose path is still present and one flag flip restores it. Phase 5 is the one-way door, and it is deliberately gated behind telemetry.

**Alternatives rejected.**
1. *Keep hardening the parser.* Rejected: three rounds, three new vectors, each fix correct. The failure rate is a property of parsing adversarial prose for a security decision, not of any particular parser.
2. *Agent writes a JSON file under `COPILOT_HOOK_STATE_DIR`.* Rejected: agents demonstrably do not receive `COPILOT_HOOK_STATE_DIR` or `CLAUDE_PROJECT_DIR`, so the path is unresolvable without a helper — and once a helper exists, the helper is the interface. Also admits malformed agent-authored JSON as a new wedge, and couples agent prompts to hook-internal layout.
3. *Helper script under `.claude/hooks/bin/`.* Rejected: `bin/` is not vendored into consuming projects. (Confirmed by the existing dead `adversarial-pass.sh` reference in `qa.md`, which this analysis surfaced as a live latent defect.)
4. *Hybrid — a prose marker pointing at a structured record.* Rejected: retains a prose parser on the decision path, so a quoted `VERDICT-REF:` reproduces the Round-2 shape. Buys nothing, because the hook already knows its own `session_id` and can query directly.
5. *Bump `PROTOCOL_VERSION` / set `PROTOCOL_HARD_MIN`.* Rejected: the shim contract does not change. A bump would emit permanent false skew warnings in every project; a hard floor would break the framework's stated rule that a project pinned to an old shim keeps running.
