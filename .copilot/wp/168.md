# Technical Design — CLI-Copilot-Owned Discord Handoff Loop ("re-arm in the tool, not the prompt")

**Target repo:** `/Volumes/Dev/Sites/COPILOT/cli-copilot`
**Routes to:** @agent-me (buildable)
**Complexity:** Medium

---

## 1. Problem & Goal

Today the Discord handoff conversation stays alive only because the AI remembers to re-launch a
one-shot `copilot discord wait`/`listen` after every `notify`. That re-arm logic lives in the user's
global `~/.claude/CLAUDE.md` — the wrong layer. Every Copilot framework (Claude Code, Codex) must
carry that instruction even if it never uses Discord.

**Goal:** move the loop OUT of AI behavioral instructions and INTO cli-copilot, so the tool owns the
wait→deliver→re-arm cycle. The AI just does work and finishes its turn; the tool decides whether to
park the session on Discord and feed the next human reply back in.

---

## 2. Feasibility Gate — Stop-hook continuation: SUPPORTED (verdict: YES)

Confirmed against the Claude Code hook contract already relied on by this ecosystem
(`/Volumes/Dev/Sites/COPILOT/claude-copilot/.claude/hooks/` + its README — uses SessionStart,
PreToolUse, SubagentStop, UserPromptSubmit; **no Stop hook is registered today**, so there is no
conflict to design around).

The Claude Code **Stop hook** fires when the *main* agent finishes responding (distinct from
SubagentStop, which the framework uses for the QA gate). Its contract:

- **Input (stdin JSON):** `session_id`, `transcript_path`, `cwd`, `hook_event_name: "Stop"`,
  `stop_hook_active` (bool — true when Claude is already continuing because of a prior Stop-block;
  provided so hooks can avoid infinite loops).
- **Output to continue the session (the mechanism we need):**
  `{"decision": "block", "reason": "<text>"}` on stdout, exit 0. `decision:block` **prevents the stop**
  and the `reason` string is fed back to Claude as the next thing it must act on. (Equivalent path:
  exit code 2 with the text on **stderr**.) This is exactly "feed an incoming Discord reply back into
  the session as the next turn's input."
- **Output to allow normal stop:** exit 0 with no `decision:block` (optionally `{"continue": true}`).
- The Stop hook runs **synchronously and blocks the harness** while it executes — so a blocking
  `wait_for_reply` *inside* the hook is the parking mechanism (intended "away" semantics).

**Conclusion:** No residual AI instruction is required. cli-copilot can own the entire loop via a Stop
hook. We do NOT use `stop_hook_active` as the terminator — our terminators are an explicit away-state
flag, a reply token, and a wait timeout (below). Because each cycle blocks on real human input (or a
timeout), there is no busy-loop; the human/timeout is the natural rate limiter.

---

## 3. Chosen Mechanism

**Put the loop brain in cli-copilot as a subcommand; make the Claude Code hook a 2-line shim.**

```
Claude main turn ends
        │
        ▼
[Stop hook shim] ──stdin JSON──▶ `copilot discord stop-hook`
                                        │
              ┌─────────────────────────┼─────────────────────────────┐
              ▼                          ▼                             ▼
   no active await-handoff      reply received                  wait timed out
   for this cwd  → exit 0       (not a token)                   → post idle notice,
   (ALLOW STOP — guard:         → emit {"decision":"block",      clear await, exit 0
   never touches an active       "reason": framed reply}         (RELEASE — graceful)
   terminal session)            exit 0  (CONTINUE)
                                        │
                            reply IS a terminator token
                            (/return, /resume-local, /stop)
                            → clear await, ack on Discord,
                              exit 0 (ALLOW STOP)
```

This satisfies "shared logic in cli-copilot; thin Claude Code adapter now, Codex adapter later as a
thin add": all decision logic is Python in cli-copilot; the Claude shim is `exec copilot discord
stop-hook`. A future Codex adapter is just another thin shim (or a Codex-flavored event translator)
calling the same subcommand.

### 3.1 Away/active state flag

Reuse the **existing handoff registry record** (`~/.copilot-cli/discord/handoffs.json`) rather than a
new state file. Add two fields to each record:
- `await: bool` — true ⇒ "this session is Discord-driven; park it on Stop."
- (existing `cwd`, `local_session_id`, `status` are reused for correlation.)

**Correlation key = `cwd`.** The Stop hook input gives Claude's `session_id` and `cwd`, but the agent
that runs `copilot discord handoff` cannot reliably know Claude's `session_id`. So the hook matches the
**open handoff whose `cwd == hook.cwd` and `await == true`** (preferring an exact `local_session_id`
match when one was supplied). Decision/limitation: **one away-session per project directory** — correct
default for real usage, flagged in §6.

Arming is **explicit** (honors the guard "engage ONLY in explicit away/active mode"):
- `copilot discord handoff --await ...` arms in one step (default `--no-await` for backward-compat/safety).
- `copilot discord await on <thread>` / `copilot discord await off <thread>` toggle it standalone.
- `copilot discord close <thread>` (already sets `status: closed`) naturally ends the loop.

### 3.2 Timeout behavior — bounded wait + graceful RELEASE (justified)

`stop-hook` calls the existing `wait_for_reply` (poll) or `listen_for_reply` (Gateway) with a timeout
from `COPILOT_DISCORD_WAIT_TIMEOUT` (default **1800s / 30 min**).

- **On timeout → RELEASE** (clear `await`, post a Discord "session idle, released — send a new handoff
  to resume" notice, exit 0 → allow stop). **Justification (SRE graceful degradation):** an
  infinite in-hook block leaves the local terminal unkillable except by Ctrl-C and silently pins the
  session forever. A bounded wait that releases cleanly is the safe default; a user who genuinely wants
  a forever-park sets `COPILOT_DISCORD_WAIT_TIMEOUT=0` (re-wait/forever, opt-in).
- **On reply → CONTINUE** (block stop, inject framed reply).

Recommend `listen_for_reply` (Gateway, event-driven, lower latency, no polling spend) as the default
inside the hook, falling back to `wait_for_reply` if websockets/Gateway is unavailable.

### 3.3 Reply framing (the injected `reason`)

The `reason` string must be unambiguous to Claude so it treats the reply as the next instruction and
keeps using Discord for output, e.g.:

```
[Discord away-mode] Reply from @<username> (this continues the current session; the tool will
re-arm automatically after you finish):

<reply content>

When done, post your result with `copilot discord notify --thread-id <tid> "<summary>"`. To end
away-mode the user can reply /return.
```

### 3.4 Escape hatches & loop termination (COPILOT_* convention)

| Variable | Effect |
|----------|--------|
| `COPILOT_DISCORD_LOOP=off` | `stop-hook` is an immediate no-op (exit 0, allow stop) |
| `COPILOT_SAFETY=off` | Also disables the loop (umbrella, consistent with /careful + /freeze) |
| `COPILOT_DISCORD_WAIT_TIMEOUT=<sec>` | Idle wait before RELEASE; `0` = wait forever |
| reply token `/return` (also `/resume-local`, `/stop`) | Clears `await`, returns control to local terminal |
| `copilot discord close <thread>` | Ends the loop (status closed) |

## 5. Failure Modes / Graceful Degradation

| Failure | Behavior |
|---------|----------|
| Discord bot token / network down inside hook | Catch, log to stderr, **exit 0 (allow stop)** — never trap the terminal on infra failure |
| Gateway (`listen`) unavailable | Fall back to `wait_for_reply` polling |
| Malformed stdin / no JSON | Exit 0 (allow stop) |
| No await-handoff for cwd | Exit 0 (allow stop) — the core guard for active terminal sessions |
| Idle past timeout | RELEASE + Discord notice (§3.2) |
| Another Stop hook later added by claude-copilot | Coexists — `hooks.Stop` is an array; install merges, never clobbers |

---

## 6. Decisions That Need the User

1. **Idle-timeout policy:** default to **bounded 30-min wait then RELEASE** (recommended, graceful) vs
   **wait-forever park**. Spec defaults to release; `COPILOT_DISCORD_WAIT_TIMEOUT=0` opts into forever.
2. **Away-state correlation = `cwd`** ⇒ **one away-session per project directory**. Acceptable default;
   confirm no need for multi-session-per-dir.
3. **Retire the global `~/.claude/CLAUDE.md` re-arm instruction.** That file is user-owned and editing
   it is the whole motivation, but it is the user's to change — @agent-me should not edit it silently;
   propose the replacement text (`handoff --await` + tool-owned loop) for the user to apply.
