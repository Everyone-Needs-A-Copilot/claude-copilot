## QA Diagnosis: Pre-existing Test Failures in claude-copilot

### Failure 1: smoke-test.sh — Agent Count
**Classification:** STALE TEST
**File:Line:** scripts/smoke-test.sh:82-85
**Root Cause:** Line 82 counts agents with `find .claude/agents -maxdepth 1 -name '*.md' -type f | wc -l`. Line 83 hardcodes `-eq 8`. Real agent count is 16 (cco, cpa, cs, cw, do, doc, ind, kc, me, qa, sd, sec, ta, uid, uids, uxd). The roster was expanded to 16 in v5.3.0 but the test was never updated.
**Fix (STALE TEST → update literal):**
- scripts/smoke-test.sh line 83: change `-eq 8` to `-eq 16`
- Also update the pass/fail message on lines 84-85: change 'All 8 active agents present' to 'All 16 active agents present' and 'expected 8 active agents' to 'expected 16 active agents'
**Robustness alternative:** Replace the literal with a dynamic count: `EXPECTED_AGENT_COUNT=       0` and then assert it matches a floor (e.g. `-ge 16`). However, since the project convention is explicit literals, updating to 16 is sufficient and consistent with how check-versions.sh already handles it (check-versions.sh already correctly says '16 expected').

### Failures 2a-2h: integration-test.sh — Routing Table Assertions (8 failures)

**Classification: ALL STALE TEST**

**Assertion (line 233):** `grep -q '| .* | .* |' ... && grep -q 'Situation.*Route To' ...`

**Reality in agents:** All four agents (ta.md, qa.md, sd.md, me.md) use the column header format:
  `| Route To | When |`
  NOT `| Situation | Route To |`

The agents ARE correctly formatted with valid markdown tables. The test assertion requires the column headers to contain 'Situation' and 'Route To' in that order, but the actual modern format is 'Route To | When'. This format has been the standard since at least v5.x — the test is checking for a deprecated column layout.

**Fix (STALE TEST → update assertion):**
- scripts/integration-test.sh line 233: Change:
  `if grep -q '| .* | .* |' "$AGENT_PATH" && grep -q 'Situation.*Route To' "$AGENT_PATH"; then`
  To:
  `if grep -q '| Route To | When |' "$AGENT_PATH"; then`
  (The pipe-table-row check is redundant once you match the header exactly)

### Failures 2i: integration-test.sh — Decision Authority Sections (4 failures same agents)

**Classification: STALE TEST**
**File:Line:** scripts/integration-test.sh:243-247

**Assertion:** `grep -q '### Act Autonomously' ... && grep -q '### Escalate' ...`

**Reality:** None of ta.md, qa.md, sd.md, me.md contain '### Act Autonomously' or '### Escalate' sections. These decision-boundary section names were apparently removed or renamed in a prior refactor. Agents now embed decision guidance inline in Core Behaviors. The agents are legitimately well-structured without these specific subsection headers.

**Fix (STALE TEST → remove or update assertion):**
- scripts/integration-test.sh lines 243-247: Either remove the check entirely, or replace with a check that actually exists, e.g.:
  `grep -q '## Core Behaviors' "$AGENT_PATH"`
  (which smoke-test.sh already checks at line 114 — so removing the decision-authority check is cleaner than duplicating a core-behaviors check)

### Failure 3: integration-test.sh — /continue missing memory_search

**Classification: STALE TEST**
**File:Line:** scripts/integration-test.sh:271-275

**Assertion:** `grep -q 'memory_search' "$CONTINUE_CMD"`

**Reality:** .claude/commands/continue.md contains zero occurrences of 'memory_search'. The command was migrated from MCP tool calls (memory_search) to cc CLI calls (cc memory search) in the same refactor that removed MCP servers. The command uses `initiative_get` and `cc memory` patterns, not the old MCP tool name. There is no regression — the command correctly refers to non-MCP tooling.

**Fix (STALE TEST → update assertion):**
- scripts/integration-test.sh lines 271-275: Change:
  `if grep -q 'memory_search' "$CONTINUE_CMD"; then`
  To:
  `if grep -q 'cc memory\|initiative_get' "$CONTINUE_CMD"; then`
  And update pass/fail messages accordingly.

### Failure 4: tests/tui/ — 61x ModuleNotFoundError: claude_monitor

**Classification: ENV ISSUE (but with important nuance)**

**Root Cause:** The `tests/tui/` directory contains tests for the `claude_monitor` package. The package source is at `src/claude_monitor/` and `pyproject.toml` defines it correctly (project name: 'claude-monitor', packages found in `src/`). However:
1. `claude_monitor` is NOT installed in the system Python or the project venv.
2. `python -c 'import claude_monitor'` → ModuleNotFoundError.
3. The package has a full `.egg-info` directory at `src/claude_monitor.egg-info/` suggesting it was once installed with `pip install -e .` but that install is now absent (likely cleared).
4. `pyproject.toml` (line 159) sets `testpaths = ['src/tests']` — so pytest by default would NOT collect `tests/tui/`. The `tests/tui/` directory sits outside the configured testpaths and is NOT the upstream project's test directory (which is `src/tests/`).
5. This appears to be a vendored/embedded sub-project (the 'Claude Code Usage Monitor' by Maciek at roboblog.eu), not a first-party claude-copilot test suite.

**Fix recommendation:** Exclude `tests/tui/` (and `tests/unit/`, `tests/integration/` if they belong to the same sub-project) from the copilot pytest run. Options:
  A. Add `--ignore=tests/tui` to the addopts in pyproject.toml (but pyproject.toml belongs to the sub-project)
  B. Add a `pytest.ini` or `conftest.py` at repo root level with `collect_ignore_glob = ['tests/tui/*', 'tests/unit/*', 'tests/integration/*']` — this cleanly excludes them without touching the sub-project's pyproject.toml
  C. Or: run `pip install -e .` in the venv first (ENV FIX) — but this only makes sense if the tui tests are meant to run as part of this repo's CI

**Additional note:** pyproject.toml `addopts` includes `--cov=claude_monitor --cov-fail-under=70`. When running tests/ that don't touch claude_monitor code, coverage is 0 and the suite fails with 'FAIL Required test coverage of 70% not reached.' This means ANY pytest run against the copilot-specific tests (test_ff6_negative.py, test_skill_frontmatter.py, etc.) will fail due to coverage enforcement on a different package. This is a secondary ENV ISSUE — the coverage config applies globally and breaks non-tui tests too.

**Fix for coverage failure:**
- The root conftest.py or a pytest.ini at repo root should override addopts to NOT enforce --cov=claude_monitor when running copilot-specific tests. Or run copilot tests with `pytest tests/ --ignore=tests/tui --no-cov -p no:cov` to bypass the sub-project coverage enforcement.

### Failure 5: check-versions.sh — nativeAgents.join() TypeError

**Classification: REAL BUG**
**File:Line:** scripts/check-versions.sh (node one-liner)
**Root Cause:** The script tries to read `VERSION.json.components.agents.nativeAgents` via node but that field doesn't exist in VERSION.json. The script runs but fails with: 'TypeError: Cannot read properties of undefined'. This is a non-critical cosmetic failure (the script does not exit non-zero from this error in isolation) but it's a real bug.
