## B. Top Candidate Adoptions

### P0 — HTML work-product renderer (`tc wp render --html <id>`)
- **What:** A read-only command that renders an *already-stored* work product (PRD, architecture/ADR,
  specification, code-review, checkpoint) to a self-contained HTML file: tabbed nav for 100+ line specs,
  tables/SVG for data-flows and boundary diagrams, color-coded severity for review findings, and —
  per the blog's load-bearing practice — **"copy as" buttons (JSON / Markdown / diff)** so the human
  stays in control and can paste results back into Claude Code.
- **Touches:** `tools/tc/` (new `render` subcommand; reuses `wp get` content path + a template).
- **Complexity:** Medium.
- **Why it matters / fit:** tc is *the* store for exactly the large artifacts the blog says Markdown
  handles badly. Rendering happens out-of-band as a side artifact (a file/link) — it returns ZERO extra
  tokens to the main session, so it reinforces (not violates) our externalize-don't-inline core purpose.
  It is genuinely novel for us and high-leverage: shareable PRD/ADR review without context bloat.
- **Trade-off:** Optimizes human reviewability/shareability; sacrifices a small amount of tc surface area
  and template-maintenance. Fully reversible (additive, read-only). Reversible: yes.

### P1 — Wire safety primitives into `pretool-check.sh` (`/careful` + `/freeze`)
- **What:** Add `rule_destructive_command` (warn/deny on `rm -rf`, `DROP TABLE`, `git push --force`,
  history deletion) and `rule_path_scope` (lock edits to a declared directory) using the **already-present**
  `security-rules.json`. `/guard` = both enabled.
- **Touches:** `.claude/hooks/pretool-check.sh` (one `rule_<name>()` + dispatch line each — the README
  documents this exact extension path), `security-rules.json` (already written), escape-hatch env vars.
- **Complexity:** Low.
- **Why it matters / fit:** Closes a *known, self-documented* gap ("aspirational… not enforced"). It
  mechanically enforces our own global CLAUDE.md reversibility/blast-radius policy that is currently
  policy-only, and the path-scope lock directly defends against Karpathy's "orthogonal edits" failure mode.
- **Trade-off:** Optimizes safety/blast-radius control; sacrifices a little agent freedom (mitigated by
  existing escape-hatch pattern `COPILOT_*=off`). Reversible: yes.

### P1 — Cross-model adversarial verification pass (optional, availability-gated)
- **What:** An optional independent-model "try to break it" review whose result feeds a NEW artifact type
  (e.g. `ARTIFACT: adversarial-run|<external-model> findings=...`) into the existing artifact-gated verdict
  in `subagent-stop.sh`. Surfaces overlapping-vs-unique findings between Claude QA/sec and the 2nd model.
- **Touches:** `.claude/agents/qa.md` + `.claude/agents/sec.md` (new optional step), `subagent-stop.sh`
  verdict/artifact parser (accept new artifact type).
- **Complexity:** High.
- **Why it matters / fit:** Our gate already enforces *external* verifiable artifacts — but all from one
  model, so it cannot catch same-model blind spots. An independent model is the strongest possible
  artifact. Must be **availability-gated and degrade gracefully** (offline-first ethos): if no second-model
  CLI is present, fall back to today's single-model artifact gate.
- **Trade-off:** Optimizes defect/vuln detection (independence); sacrifices an external dependency +
  determinism + offline guarantee unless gated. Reversible: yes (additive, optional).

### P2 — In-flight Confusion Protocol as a shared agent loop-state
- **What:** Promote Flow D from entry-only to a first-class agent behavior: on a *genuinely ambiguous
  decision* mid-task, an agent emits a clarifying-question promise (akin to `<promise>BLOCKED</promise>`)
  instead of guessing.
- **Touches:** CLAUDE.md Agent Shared Behaviors + Iteration Loop; agent frontmatter loop states.
- **Complexity:** Low.
- **Why / caveat:** Partially overlaps the global Autonomy "pause and ask" rule — frame as making it a
  named loop-state (not a duplicate). Reversible: yes.

### P2 — `cc memory export` (the valuable half of `/learn`)
- **What:** Export project-specific patterns/lessons/decisions to a portable bundle. Pairs with existing
  `/reflect` + `cc memory delete` (prune).
- **Touches:** `tools/cc/`. **Complexity:** Low. Reversible: yes.

### P2 — Renderer templates: exploration grids + rendered-diff code review
- **What:** Once P0 exists, add template variants — a side-by-side variant grid for the design chain
  (uids/uid) and a rendered-diff-with-inline-annotations template for qa/sec output.
- **Touches:** `tools/tc/` templates + design/qa agents. **Complexity:** Medium. Reversible: yes.

## C. Recommend SKIP (does not fit our philosophy)

| Skip | Why |
|------|-----|
| `[gstack-context]` WIP-commit checkpoints + `/context-restore` from commit bodies + `/ship` squash | Duplicates Memory Copilot + `/pause`/`/continue`; would pollute git history. We ship via PR with signed commits and value clean history (see memory: claude-copilot PR workflow). Our tc/memory checkpoint is the cleaner mechanism. |
| `/retro` normalized metrics (logical LOC, per-person, streaks) | Vanity metrics; conflicts with No-Time-Estimates + anti-generic ethos. `cc usage` already covers opt-in telemetry. A light memory-mining retro is marginal at best. |
| Cross-agent portability (one config across Codex/Cursor/etc.) | Our hooks bind to Claude Code lifecycle events by design; we are CC-native. Out of scope, large surface, low payoff. |
| Taste memory with 5%/week decay | Niche (design prefs only); `cc memory check` already handles staleness. Revisit only if design-pref drift becomes a real pain. |

## D. Prioritized Recommendation Table

| Pri | Adoption | Component | Complexity | Phase |
|-----|----------|-----------|-----------|-------|
| **P0** | HTML work-product renderer `tc wp render --html` + "copy as" buttons | tools/tc | Medium | Phase 1: Foundation |
| **P1** | Wire `/careful` + `/freeze` safety rules into pretool-check.sh | .claude/hooks | Low | Phase 1: Foundation (parallel to P0) |
| **P1** | Cross-model adversarial verification (availability-gated artifact) | qa.md, sec.md, subagent-stop.sh | High | Phase 2: depends on QA-gate stability |
| **P2** | In-flight Confusion Protocol loop-state | CLAUDE.md + agents | Low | Phase 2 |
| **P2** | `cc memory export` | tools/cc | Low | Phase 2 |
| **P2** | Renderer templates: variant grids + rendered diffs | tools/tc + design/qa | Medium | Phase 3: depends on P0 |

**Headline:** P0 = HTML work-product renderer (novel, high-leverage, token-free side artifact aligned with
our externalize core purpose). P1 = wire the already-scaffolded safety primitives (low-cost, closes a
self-documented gap) + availability-gated cross-model adversarial QA pass (strongest possible artifact).
