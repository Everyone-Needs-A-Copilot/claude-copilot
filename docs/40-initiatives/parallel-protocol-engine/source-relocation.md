# Safe source relocation before authoring-worktree retirement

The integration closeout exposed a real contract-amendment defect: a local CSE-relative authoring-worktree scope could not be replaced by the same repository's committed external source, because the amendment gate required every original local path string to remain present. That left the QA source locator dependent on a temporary checkout and correctly prevented its retirement.

The correction is confined to `tools/tc/src/tc/services/execution.py`. Every removed local scope must resolve without filesystem aliases to an existing source in a Git worktree. A registered external entry must have both the identical canonical Git common directory and unchanged origin; an unrelated clone with the same remote string is refused. Its committed path coverage must contain the original repository-relative scope, and that exact scope must exist at the verified commit, so a broader directory cannot hide a missing file. Normal external manifest validation still rejects unsupported entries, missing refs and missing scopes. Unmatched local removal retains the original narrowing refusal.

Successful amendments append `source_relocations` proofs with the original local path, enclosing repository, repository-relative scope, canonical Git common directory, origin, registered external repository/checkout, verified immutable commit and containing coverage path. The original contract, changed contract, source identities, owner decision and prior round remain in the existing append-only audit. Criterion IDs/order, settled attempts, failure/progress guards, checkpoints, lifetime usage, budget approvals and ordinary frozen-update rules are unchanged. The amendment still invalidates old QA and grants no fresh acceptance.

Verification used the engine worktree through `PYTHONPATH=tools/tc/src` and the existing Homebrew Python 3.14 pytest runner; the installed tc Python also compiled both new files. The four focused suites (`test_execution_source_relocation.py`, unchanged `test_execution_amendment.py`, unchanged `test_qa_external_sources.py`, unchanged `test_execution_limits.py`) passed 145 tests in 33.92 seconds. Tests use real Git repositories/worktrees and SQLite, check exact persisted history/usage, and cover related worktrees, unrelated repositories, same-origin unrelated clones, narrower scopes, missing committed files, invalid refs, changed origin, missing locators, in-root and escaping aliases, and a retained-local/broader-external combination.

Evidence remains at `/Volumes/Dev/Sites/CSE/.copilot/orchestration-build-20261104/source-relocation-before.txt`, `source-relocation-after.txt` and `source-relocation-final.txt`. The initial two positive tests reproduced the original refusal before implementation. Two initial alias cases had a fixture error (the source capturer already refused aliases during initial registration); those new fixtures were corrected to introduce alias drift after valid registration, preserving the same refusal requirement. No existing test file or assertion was edited. No real project task contract was amended by this implementation stream, and no worktree or source data was deleted; integration applies the proven relocation through the existing owner-authorized amendment API and reruns current QA.

## Directory-member coverage correction

Independent QA then demonstrated that checking only the directory object allowed a committed `docs` directory to omit an originally covered descendant. The follow-up inventories every materialized local file and directory using the existing QA manifest/exclusion rules, including new and untracked descendants, and checks each corresponding repository-relative member against the verified committed Git listing. Missing members, type substitutions and unique empty directories refuse relocation atomically. Normal QA-excluded runtime/generated directories remain excluded; nothing is silently treated as committed just because its containing directory exists. The audit now includes covered file/directory counts and the inventory digest.

The retained failing probe is `independent-qa/relocation-directory-probe-first.json`; direct added regressions reproduce moved tracked members, untracked members, nested untracked members and empty unique directories before the implementation (`source-relocation-directory-before.txt`). The unchanged covered-directory positive plus new inventory/exclusion positive pass. The final four-suite run passed 150 tests in 35.99 seconds (`source-relocation-directory-final.txt`), with all original forbidden-narrowing, amendment history, external-source and execution-limit assertions unchanged. Synthetic moved files remain preserved at their alternative paths; no source or fixture content was deleted.
