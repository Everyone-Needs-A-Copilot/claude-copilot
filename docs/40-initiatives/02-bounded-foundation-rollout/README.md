# Bounded foundation rollout

> Mode: Initiative
>
> Execution authority: Claude Copilot `tc` PRD-6 / TASK-67–70; native Codex companion tasks link their own database.

This is the implementation batch approved after the CSE framework comparison.
It has a finite finish line, not a continuing mandate to optimize the ecosystem.
Shared behavior belongs in Claude Copilot's `cc`/`tc`; Claude and Codex retain
their native entrypoints and hook contracts.

Start with the [foundation entry guide](../../30-operations/16-foundation-entrypoint.md).
The [security and merge-check receipt](../../30-operations/17-security-and-merge-check-triage-2026-09-09.md)
separates local corrections from unchanged GitHub policy and alert state.

## Finish line

| Deliverable | Required acceptance | Not a completion claim |
| --- | --- | --- |
| One local status view | `cc status` explains observed foundation/runtime and verification state; missing measurements stay unknown; no probes, inference, uploads or task approval | Live agent telemetry or subscription billing |
| One foundation entry path | Use existing setup/reconciliation; explain explicit optional capabilities; review upstream drift and exercise disposable native consumers | Global rollout, runtime trust, signed release or every consumer updated |
| Security and merge-check triage | Inspect current alerts/checks and fix only safe scoped source issues; retain exact externally unresolved requirements | Security certification, dismissed alerts or weakened branch protection |
| A stopping contract | Both protocols and engineering/QA guidance freeze scope, require current evidence and stop after approval | All historical tasks or application pilots completed |

The final pass covers changed behavior and affected integration boundaries with
recorded execution caps. Each required criterion needs its own current `tc`
approval. New findings are classified once: caused by this batch and repaired,
blocking a required criterion and reported, or unrelated and separately tracked.
An exhausted cap is incomplete, not permission to retry indefinitely. Successful
acceptance ends this batch. No second polish pass or automatic next phase follows.

## Remaining recommendations have explicit prerequisites

The [pilot handoff](phases/02-opt-in-pilots.md) makes the remaining work executable
through existing owners. It does not pretend the experiments happened. Existing
Claude TASK-64–66 retain optimization, real UI pilot and matched measurement work;
their acceptance is not replaced by this foundation batch.

No application/defect or approved personal rule has been selected for those
pilots. A source checkout is not a deployed or trusted runtime. These distinctions
are part of completion, not reasons to keep adding work to this batch.

See the [architecture decision](decisions/ADR-001-finite-delivery.md) and
[closure record](retrospectives/README.md). Detailed evidence and live state remain
