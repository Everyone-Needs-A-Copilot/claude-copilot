## Additional confirmed findings

### F5 — High: failed Codex refresh leaves rewritten configuration while publish reports restoration

**Repository/revision/source:** Claude `ee616244469678596c9f896b30fe517ed28abeb9`; `tools/cc/src/cc/core/release/publish.py:217,234–245` and `_restore` at `168–182`; `tools/cc/src/cc/core/release/codex/step.py:75–95`. These files are additions against comparison base `e4578de8f1269d5968356008b0db535cf7ada1f2`, so this recovery gap is in the audited update.

**Trigger:** a release reaches the Codex step; `config.apply` persists its marketplace/plugin changes, then marketplace upgrade and plugin-add fail. This can occur during a first conversion from legacy marketplace configuration or whenever the selected release changes enabled plugins.

**Expected:** after failed publication, restore both prior pointer and configuration bytes, or explicitly report incomplete restoration. **Actual:** the pointer returns to the previous release and `PublishError.restored` is `true`, but configuration remains rewritten. In the private reproduction, config SHA-256 changed from `1aa0de69c1bca9c2538f46ef9236b1ab19452f468108b92f9677c5b64999a264` to `9217538b0cd6e96b20f16bbb1767463fe1b6b1ac7d4b3d1239664feeee9cf994`; the original legacy plugin enablement was replaced. The direct control—successful refresh followed by failed doctor—restored the original configuration bytes and pointer.

**Cause/impact:** `config_changed` is assigned only after `codex_step.run` returns. Exceptions after its real config write leave that flag false, so `_restore` skips config rollback and still reports success. Consumers can retain failed-release enablements/configuration even though the pointer and recovery status suggest the prior state is restored. This is recovery integrity and availability, not a demonstrated privilege escalation.

**Evidence:** [reproducer](/private/tmp/cr-e2e-convergence-p_sztjaa/repro_publish_restore.py), [raw result](/private/tmp/cr-e2e-convergence-p_sztjaa/restore-result.json), preserved before/after TOML under each case directory. Exact selection was the two-case private harness, not a test file or suite. It ran candidate publisher, config, pointer, link-plan persistence and doctor; prepared build/trust inputs and outbound Codex responses were substituted. These substitutions isolate recovery and do not prove artifact authorization or genuine installation. Both cases completed; observed case times were approximately .003/.004 seconds and are not release timings. Authority worker independently read the source and challenged both cases.

**Smallest correction:** make the configuration transaction and its rollback ownership explicit before any fallible refresh/cache work, or return the successful config mutation state through the failure path. Do not blindly restore an older unrelated receipt. Only report complete restoration after every required state restoration has succeeded.

**Exact defect verification after a separately authorized fix:** rerun the same refresh-failure reproducer with byte-identical config and pointer restoration required, plus the later doctor-failure direct control. Exercise cache-validation failure if its error propagation uses a distinct changed path. Preserve the original failing evidence; do not alter assertions to permit configuration drift.

### F6 — High: explicit rollback skips required Codex refresh and doctor

**Repository/revision/source:** Claude `ee616244469678596c9f896b30fe517ed28abeb9`, `tools/cc/src/cc/commands/release.py:79–90`; `core/release/engine/pointer.py:164–185`; `core/release/publish.py:134–142`. The accepted [ADR-001](decisions/ADR-001-central-release-pointer.md), Decision 8, requires rollback to rerun marketplace refresh and doctor; its later “Final behaviour” section does not replace this requirement.

**Trigger:** run `cc release rollback --to <old-release> --home <private-home>` when the selected old release's pinned Codex cache is absent. **Expected:** refresh the selected old release, validate it, and surface refresh/doctor failure rather than report clean completion. **Actual:** the actual PATH-selected candidate CLI exited 0 and emitted the rollback record after changing the pointer; the logging/failing Codex stub was never called, and the real cache verifier reported `codex-copilot: cache version 1.0 missing`.

**Cause/impact:** the command calls pointer rollback with only a link-plan callback. The callback applies links; it does not refresh Codex or run doctor, and no lazy recovery exists in the inspected command path. A successful rollback response therefore does not establish restored consumer readiness. Missing cache was proved; actual Codex runtime breakage was not exercised. This is distinct from F5: adding error-state propagation to publication would not implement the missing explicit rollback steps.

**Evidence:** [exact CLI reproducer](/private/tmp/cr-e2e-convergence-p_sztjaa/repro_rollback_refresh.py), [raw result](/private/tmp/cr-e2e-convergence-p_sztjaa/rollback-refresh/result.json). CLI elapsed .356 seconds; source runtime was candidate cc through the retained locked Python environment. Prepared manifests were schema-complete synthetic records, not signed production releases; their deliberately missing cache isolates the contract omission. A [direct cache control](/private/tmp/cr-e2e-convergence-p_sztjaa/rollback-cache-control/result.json) shows that a matching real fixture directory yields no cache problems, while the same pinned version under an absent directory is rejected. Authority independently challenged the accepted contract, callback chain and lack of lazy refresh; no whole test file ran.

**Smallest correction:** have the canonical rollback orchestration restore the selected release's dependent Codex state, run doctor and propagate a failed/incomplete status. Keep atomic pointer/history ownership and owner-content preservation; the CLI launcher should continue delegating to this canonical path.

**Exact defect verification after a separately authorized fix:** use this missing-cache fixture with refresh failure to require nonzero/incomplete output, and a working private refresh control that populates the pinned old cache and passes the selected readiness checks. Verify pointer/history and configuration state on each failure path affected by the correction; preserve unrelated accepted checks.
