SMELL-08 mock_only_assertions REWORKED (v2) after ground-truth failure: v1 fired on ANY mock and missed both flagship true-positives (convoco test_update_conversation_persists_capture_draft_fields, research-copilot forces.test.ts nullable-fields) because each carried a nominally-real assertion alongside the mock assertion, while control repo cli-copilot-internal (no ORM writes) fired at 6.7% -- higher than convoco (0.58%) or insights-copilot (0.42%). Two fixes: E1 scoped detection to DB-SESSION mocks only (Python: verb in add/add_all/commit/flush/refresh/execute/delete/merge/begin/scalar/scalars, or mock var name matches db/session/sess/conn/connection; JS: receiver shaped like (mock)?(prisma|db|database|repo|orm)... with write verb create/update/delete/upsert/createMany/updateMany/deleteMany/transaction/save) -- HTTP-client, logger, event-publisher, and React callback-prop mocks are explicitly out of scope and now block firing like a real assertion would. E2 added AST-local tautology detection: an assert/expect is NON-REDEEMING (doesn't rescue the test) when it reads back an attribute of a test-only container (SimpleNamespace/Mock/MagicMock/AsyncMock/dict/@dataclass in Python; a var passed to .mockResolvedValue() in JS) compared to a literal the test itself supplied, or a round-trip identity check on that same container; JS also treats a bare .status/.statusCode check with no body assertion as non-redeeming. Post-fix results: cli-copilot-internal control DROPPED from 6.7% to 0.00% (0/1654 tests); convoco 0.18% (11/6017), insights-copilot 0.12% (5/4261) -- both now meaningfully above the 0% control, achieving discrimination. research-copilot (JS) 1.04% (12/1158), all manually spot-checked as genuine ORM-write-verified-only tests. All 6 acceptance cases (2 MUST-FIRE, 4 MUST-NOT-FIRE) pass. Recommendation: promote from advisory-only toward a stronger advisory signal (surfaced prominently in QA review, not auto-blocking) -- the false-positive rate is now low enough to trust the findings list, but the detector still under-fires (documented, not fabricated) on unconventionally-named session mocks and multi-hop JS dataflow, so it should not gate CI on its own.
