SMELL-08 mock_only_assertions added to pytest_smell.py and jest_smell.py: fires when every assertion in a test is a mock-call verification (assert_called*/assert_awaited*/toHaveBeenCalled*) with >=1 positive. Does not fire when all mock assertions are negative, or when any real (non-mock) assertion is present. Severity WARN, advisory-only recommended. D3 ground truth: correctly silent on both MUST-NOT-FIRE cases (negative-only mock, HTTPException.status_code checks); MISSES both named MUST-FIRE flagship examples (convoco test_update_conversation_persists_capture_draft_fields, research-copilot forces.test.ts nullable-fields test) because both carry an accompanying real (though arguably tautological/self-referential) assertion alongside the mock assertion -- catching those requires dataflow/taint tracing this AST/regex-only detector does not do; documented as a known limitation rather than weakened to force a match. D4 blast radius: convoco backend 35 hits/6017 tests (0.58%), insights-copilot 15/3587 (0.42%), research-copilot 63/979 test blocks (6.4%). Control scan of cli-copilot-internal (no ORM writes, legitimate outbound-boundary HTTP mocks) fired 123/1844 (6.7%) -- confirms real false-positive risk on outbound-boundary and UI-callback-prop tests (e.g. React onClick verification), not just the CLI case named in the task. Recommendation: ship as WARN/advisory, never blocking, until an outbound-boundary/UI-callback exclusion heuristic exists.
