# First use, repeated use and recovery

Map the first meaningful user outcome and the shortest understandable path to it.
Explain why a permission or setup step is needed where that knowledge helps the
decision. Reuse existing accounts, state and configuration; avoid another welcome
flow that repeats information already supplied.

Empty states distinguish genuinely empty data from loading, filtering, permission
limits and errors. Offer a relevant action when one exists. Preserve the user's
input on failure and make retry, cancellation, reversal and escalation explicit.
Do not invent sample records that users could mistake for persisted work.

For repeat users, protect scanability, consistent control placement, keyboard
access and stable geometry. Make advanced options discoverable without burying
frequent tasks. Use dialogs only when interruption or protected focus is warranted;
verify focus entry/return, Escape behavior and background interaction.

Walk through success, alternate and recovery paths using realistic data. Include
returning users, expired sessions, partially completed setup, offline conditions
and changed permissions where relevant. Define observable criterion IDs before
implementation and hand the flow, state matrix and unresolved service dependencies
to the next specialist through the existing specification and walkthroughs.
