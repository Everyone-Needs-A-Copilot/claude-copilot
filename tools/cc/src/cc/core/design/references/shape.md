# Surface intent and interaction brief

Name the actual visitor task and surface before choosing visual treatment. One
product can contain all four modes: persuade (make an informed decision), operate
(complete work), read (understand), experience (engage with the work itself).
Modes describe success; they are not style presets or permanent product labels.

Read existing product facts and the requested target. Record the audience, usage
frequency, environment, primary action, real content, and success criterion. Carry
unresolved material facts forward explicitly; ask only when an answer changes the
work and cannot be recovered from existing evidence. Never invent metrics, social
proof, capabilities or owner preferences to fill a layout.

Map the journey, alternate paths, recovery, and handoffs before screen polish.
Name relevant default, empty, loading, success, error, disabled, permission and
overflow states. Specify minimum, typical and maximum data ranges. Identify the
information hierarchy, keyboard/focus path, decision points and responsive changes.
For operation-heavy surfaces, preserve familiar affordances and rapid repeated use;
for reading, prioritize comprehension; for persuasion, support a truthful decision;
for experiences, let the actual work carry the attention.

Store the specification in the current task and reference the existing product
and design authority. A design contract records this scope for subsequent review;
it does not replace the PRD or create another task board. Preserve CSE's required
UX and UI walkthroughs when applicable. Hand off a named target, criterion IDs,
states, constraints, source references and explicit unknowns to visual design.
